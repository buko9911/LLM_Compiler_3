# 코어 의존성·활성값 상주·가중치 선행 적재

2026-09-18. 같은 Llama 디코더 한 층 캡처, prefill 32토큰, 4코어,
동일한 시뮬레이터 설정으로 단계별 실행을 비교한다.
기준은 이전 DMA 검토의 비동기 Local DMA 구현(38,580,452사이클)이다.

## 1. 실제 행 구간으로 전역 의존성 추적

`Access`에 행 수와 stride를 추가하고 타깃 IR의 선택 속성 `read_rects`,
`write_rects`에 `(offset, row_bytes, rows, stride)`를 보존한다.
기존 `reads`, `writes` 쌍은 그대로 지원한다. Unified Program v5 형식은 바뀌지 않는다.

스케줄러는 행 사이의 빈 공간을 접근으로 취급하지 않는다. 서로 다른 출력 열을
쓰는 코어는 독립적으로 실행하고 실제 겹치는 RAW/WAR/WAW와 코어 내부 순서는
보존한다. GDMA도 같은 규칙을 적용한다. 전체 사각형의 마지막 행까지 용량을
검사하며 오버플로가 발생하는 크기는 거부한다.

## 2. 코어별 활성값 캐시

현재 대상은 M≤32, 전체 K가 한 L1 타일에 들어가고 N 패널이 여러 개인 matmul이다.
기존 임시 L1 할당의 최대 주소 뒤에 남는 공간만 사용한다. 코어별 캐시에는
DRAM 원본 뷰와 현재 보관 중인 내용을 대응시킨다. L2 주소가 같다는 이유만으로
재사용하지 않으며, 원본 DRAM 쓰기가 발생하면 관련 캐시를 무효화한다.

이 Llama에서는 코어당 256 KiB가 사용되고 L2→L1 적재 596회, 149 MiB가 생략된다.
L1 여유가 없거나 원본 대응 관계를 증명하지 못하면 기존 전송을 사용한다.

캐시 주소로 기존 활성값의 모든 사용자를 바꾸지는 않는다. 이전 활성값이 살아
있는 동안 다른 matmul이 캐시를 교체할 수 있기 때문이다. 기존 버퍼의 수명을
유지하고 캐시에서 그 버퍼로 L1 내부 복사를 한다. 이 비용은 아래 실측에 포함된다.
DRAM→L2의 반복 활성값 적재까지 제거하는 구현은 아니다.

## 3. 같은 코어 블록 안에서 다음 가중치 선행 적재

다음 가중치의 비동기 적재를 이전 MMA 바로 뒤로 옮겨, 이전 타일의 writeout과
`C_WAIT_MATRIX`보다 먼저 발행한다. 이동 구간의 L1 접근, L2 쓰기, 현재 출력과
충돌하면 이동하지 않는다. `C_WAIT_LDMA`를 포함하는 전송도 이동하지 않으며,
코어 블록 경계와 VPU 연산은 넘지 않는다.

현재 시뮬레이터는 M_LOAD에서 피연산자를 별도 스냅샷으로 읽고 L1 읽기 완료와
덮어쓰기 의존성을 추적한다. 따라서 이 경우에는 기존 가중치 L1 버퍼를 재사용할
수 있어 가중치 버퍼를 한 벌 더 할당하지 않는다. 배열 누산기는 기존처럼 하나이며
출력 완료에 필요한 대기를 제거하지 않는다.

이 Llama에서 가중치 전송 608회, 152 MiB에 대해 선행 발행이 적용된다.
이 수치는 전송량 감소가 아니라 발행 순서 변경이다.

## 실측

| 단계 | 사이클 | 직전 단계 대비 감소 | 기준 대비 감소 |
|---|---:|---:|---:|
| 기준: 이전 비동기 DMA | 38,580,452 | 0.00% | 0.00% |
| ① 전역 의존성 정밀화 | 27,623,799 | 28.40% | 28.40% |
| ①+② 활성값 상주 | 26,185,950 | 5.21% | 32.13% |
| ①+②+③ 가중치 선행 적재 | 25,917,200 | 1.03% | 32.82% |

모든 단계의 최종 출력은 이전 PyTorch 검증을 통과한 기준 출력과 비트 단위로 같다.
최종 프로그램은 별도 빌드에서 재생성한 `program.bin`, `system.json`, `metadata.json`과도
바이트 단위로 같다. 다른 모델·시퀀스 길이·하드웨어의 개선율을 보장하는 수치는 아니다.

## 검증과 산출물

- 단위 테스트: 분리된 출력 열의 독립성, 실제 겹침, GDMA 행 사이 빈 공간, 용량 초과.
- 드라이버: DRAM 쓰기 후 캐시 무효화, L1 공간 부족 시 기존 경로, IR 저장·재파싱.
- 시뮬레이터: 다중 패널·4코어 matmul에서 캐시/선행 적재가 실제 발생하는지 검사하고,
  동일 배치에서 두 최적화를 끈 대조 프로그램 및 PyTorch와 비트 단위 비교.
- 기존 작은 L1의 K 분할, FlashAttention, elementwise 등 통합 테스트를 유지한다.

재현용 빌드 및 테스트:

```sh
/home/jjh4777/tools/cmake-3.29.6-linux-x86_64/bin/cmake --build build/pipeline-build -j 2
/home/jjh4777/tools/cmake-3.29.6-linux-x86_64/bin/ctest --test-dir build/pipeline-build --output-on-failure
```

`build/pipeline-review/step1`, `step2-fixed`, `final`에 단계별 프로그램, 시뮬레이터 로그,
타임라인과 출력 덤프가 있다. `comparison.json`은 수치 검증과 사이클 요약이다.
`step2`, `step3`는 개발 중 산출물이므로 최종 비교에 사용하지 않는다.
`cache-only.mlir`는 최종 placed IR에서 가중치 선행 적재 표시만 제거한 대조 입력이다.
